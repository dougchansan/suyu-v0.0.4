## What was actually available

The sandbox was Linux x86-64. Direct GitHub cloning failed because external DNS was unavailable.
Selected source was read through the connected GitHub API and reconstructed in a **partial
checkout**, verifying the original Git blob hashes before modifying it:

| Original file | Verified Git blob SHA |
| --- | --- |
| `src/core/perf_stats.cpp` | `747ea3eac6dcccead573815c3cb2ba3977ac4636` |
| `src/core/perf_stats.h` | `dd6becc02dd9eb281ef39f2ff29ddb9689f727e7` |
| `src/core/arm/recomp/arm_recomp.h` | `56257c5e4ee6115dd286274f8516cc5373f1e4e7` |

The telemetry producer and process setup/shutdown ordering were also inspected through GitHub.
The actual modified `perf_stats.cpp` was compiled, but its unrelated filesystem/settings/fmt
includes and runtime counter providers were replaced by **explicit component-test doubles**.
The doubles are generated by `tests/aot/make_support.py`; they are not production replacements.

No game binary, generated commercial-game code, keys, firmware, iPhone, Apple SDK or Metal
device was present. No guest game was executed. The complete Suyu core, Qt frontend, static
export pipeline and iOS application were **not built or validated** in this sandbox.

## Results

| Build/test configuration | Result |
| --- | --- |
| GCC 14.2.0, Release, warnings as errors | All 3 CTest groups passed |
| Clang 17.0.0, Release, warnings as errors | All 3 CTest groups passed |
| Clang 17.0.0, Debug, ASan + UBSan, leak detection | All 3 CTest groups passed; no sanitizer findings |
| Python 3.13.5 | All 32 unittest cases passed, including generated C++ trace round trips |
| Concurrent production frame-counter test | Exactly 400,000 events consumed per run |
| Repeated concurrency stress | 20/20 runs passed; 8,000,000 events consumed exactly |
| Deliberately restore load-then-reset race | Regression test failed as expected |
| Deliberately restore zero-frame division | Regression test failed as expected |
| Python syntax compilation and `git diff --check` | Passed |

Each CTest configuration runs 44 C++ metrics checks, 8 production-PerfStats component checks,
and the 32 Python test cases. The latter include table-driven invalid-input subtests. All trace
fixtures are synthetic. Counts are test events, **not rendered gameplay frames**. Passing these
tests does not measure JIT-vs-AOT performance or establish iPhone compatibility.

The two intentionally broken variants were created outside the source tree and were never
committed. Their observed diagnostics were:

```text
lost-frame-reset: exit=1
FAILED: no frame loss across concurrent resets

zero-frame-divide: exit=1
FAILED: zero-frame query
```

## Reproduction

```sh
cmake -S tests/aot -B build-aot-gcc -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=g++
cmake --build build-aot-gcc --parallel 2
ctest --test-dir build-aot-gcc --output-on-failure -V

cmake -S tests/aot -B build-aot-clang -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=clang++
cmake --build build-aot-clang --parallel 2
ctest --test-dir build-aot-clang --output-on-failure -V

cmake -S tests/aot -B build-aot-sanitized -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_COMPILER=clang++ -DAOT_TEST_SANITIZERS=ON
cmake --build build-aot-sanitized --parallel 2
ASAN_OPTIONS=detect_leaks=1 UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir build-aot-sanitized --output-on-failure -V
```

The included GitHub workflow configures independent Linux and macOS component jobs. Its presence
is not a claim that remote CI or AppleClang has already passed. Full-core builds with real
dependencies and signed-device execution remain required before promoting this architecture
foundation to an iOS-ready implementation. See `jit-free-aot.md` for the complete boundary,
measurement semantics and remaining validation gates.
